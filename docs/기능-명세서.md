```
├─ signup.tsx             이메일 가입 + 약관 동의

├─ (tabs)/                플로팅 탭바 5개
│   ├─ index.tsx          지도
│   ├─ feed.tsx           피드
│   ├─ community.tsx      모임 목록
│   ├─ chat.tsx           채팅방 목록
│   └─ profile.tsx        내 프로필
├─ create-post.tsx        게시물 작성
├─ create-gathering.tsx   모임 만들기
├─ post/[id].tsx          게시물 상세
├─ gathering/[id].tsx     모임 상세
├─ user/[uid].tsx         타 유저 프로필
├─ shared-map/[uid].tsx   타 유저 지도 보기
├─ dm/new.tsx             새 DM (유저 검색)
├─ dm/[roomId].tsx        채팅방 (DM/모임 공용)
└─ notifications.tsx      알림 목록
```

**네비게이션 가드 (`_layout.tsx`)** — 상태 3개(로그인 여부, `profile_complete`, 폰트)가 모두 확정될 때까지 흰 화면 + 스피너 오버레이를 덮는다.

| 조건 | 이동 |
|---|---|
| 비로그인 & 탭 영역 | `/login` |
| 로그인 & 로그인/가입 화면 | `profile_complete`면 `/(tabs)`, 아니면 `/profile-setup` |
| 로그인 & 프로필 미완성 & 설정 화면 아님 | `/profile-setup` |
| 로그인 & 프로필 완성 & 설정 화면 | `/(tabs)` |

로그인 판정은 `firebaseUser || kakaoUser`. 카카오 유저의 uid는 `kakao_{카카오ID}`이며, 화면마다 `firebaseUser?.uid ?? (kakaoUser ? 'kakao_'+id : null)`로 반복 계산한다(훅 하나로 통합 권장).

**탭바** — 화면 하단에 떠 있는 커스텀 바(`FloatingTabBar`). 채팅 탭 아이콘에 전체 방의 `unread_counts[myUid]` 합계를 배지로 표시(99+ 캡). 지도 탭의 바텀시트는 탭 레이아웃 위에 오버레이로 렌더링한다(Modal 아님).

## 3. 기능 상세

### 3.1 인증 (AUTH)

| 방식 | 흐름 | 비고 |
|---|---|---|
| 이메일 | `createUserWithEmailAndPassword` → 유저 문서 생성 / `signInWithEmailAndPassword` | 비밀번호 6자 이상, 확인란 일치 검사, 닉네임 필수 |
| 카카오 | 시스템 브라우저 OAuth → `code` → 토큰 교환(`kauth.kakao.com`) → 사용자 정보 조회 → **CF `kakaoCustomToken`** 호출 → `signInWithCustomToken` | 유저 문서 upsert는 **서버가 전담**. 세션은 `expo-secure-store`에 저장, 앱 시작 시 복원 |
| 구글 | `accounts.google.com` 을 `openAuthSessionAsync`로 열어 **implicit `id_token`** 수신(nonce 사용) → `signInWithCredential` | 리다이렉트용 정적 페이지 `public/google.html` (Firebase Hosting). 웹 클라이언트 ID 사용 |
| 애플 | `expo-apple-authentication` (iOS만 버튼 노출) → `OAuthProvider('apple.com')` credential | nonce 해시 사용 |

**약관 동의 (AUTH-06, 원스토어 심사 대응)**
- 필수 3개: 이용약관 / 개인정보 처리방침 / 위치기반서비스 이용약관(위치정보 수집·이용). 각 항목은 전문 보기 모달 제공, 본문은 `TermsAgreementSection.tsx`에 하드코딩.
- 이메일 가입: 3개 모두 체크해야 가입 버튼 통과.
- 소셜 로그인: **기기당 1회**만 노출(`SecureStore`의 `terms_agreed_locally`). 이미 동의한 기기에서는 체크 UI 없이 진행.
- **서버 재검증**: 신규 유저이고 `agreedToTerms !== true`면 카카오 CF가 `failed-precondition`으로 거절. 클라이언트 `createUserDoc`도 같은 검사를 한다.
- 신규 유저 문서에 `terms_agreed_at`, `location_consent: true` 기록.

**신규 유저 문서 기본값**: `points 0, sheriff_score 0, badge_list [], saved_places [], followers [], following [], blocked_users [], rank_level 'rookie', is_home_verified false, profile_complete false`.

### 3.2 온보딩 (`profile-setup`)
- 닉네임(최대 20자, 카카오는 카카오 닉네임 프리필, 이메일/구글/애플은 Firestore 값 프리필) + 거주지역 3단 선택(`KOREA_DISTRICTS` 상수: 시도→시군구→읍면동, 266줄 정적 데이터).
- 저장 시 `nickname`, `home_address`(전체 주소 문자열), `profile_complete: true` 기록 후 탭으로 이동.
- ⚠️ 여기서 저장되는 `home_address`는 **자기 신고 값**이다. GPS 인증(`is_home_verified`)과 별개이며, 월간 보안관 집계(§3.9)는 이 값만 본다.

### 3.3 지도 (`(tabs)/index.tsx`, 2,326줄 — 가장 큼)

**구조**: React Native ↔ WebView 양방향 메시지 브리지.
- RN → 웹: `injectJavaScript('handleRNMessage(...)')`. 메시지 타입: `SET_LOCATION, MY_LOCATION, CENTER, GO_TO, SET_MODE, SHOW_PLACE_MARKERS, CLEAR_PLACES, UPDATE_APP_PINS, SET_DRAGGABLE, DRAW_ROUTE, DRAW_ROUTE_SEGMENTS, CLEAR_ROUTE`
- 웹 → RN: `MAP_READY, MAP_CENTER, PIN_PRESS, PLACE_PRESS, MAP_PRESS, WV_ERROR` (수신 시 타입 가드 `isMapPin`/`isPlaceResult`로 검증)
- 초기 줌 level 5, 서울 시청(37.5665, 126.9780)을 기본 중심으로 사용.

**3가지 모드** (좌상단 드롭다운, 스프링 애니메이션)

| 모드 | 표시 내용 |
|---|---|
| 기본(`basic`) | 게시물 핀(파랑, `location_pin` 있는 게시물) + TourAPI 관광지 마커. 진입 시 주변 관광지 자동 로드(반경 2km, 15개, 최초 1회) |
| 내 지도(`my_map`) | 내가 저장한 핀(초록)만. 지역 필터 없음 |
| 모임(`gathering`) | 모집 중 모임 핀(주황, 번개는 번개 아이콘) **가까운 15개** + 내 랜드마크 핀(§3.4). 카테고리 칩(`전체/⚡번개/산책·운동/맛집/문화·예술/스터디/취미/봉사`)과 텍스트 검색(제목·장소명·소개) |

> 초기 기획의 "Basic / My Own / **Quest**" 3탭 중 Quest는 구현되지 않았고, 대신 "모임" 모드가 들어갔다.

**위치**: `expo-location` 포그라운드 권한 요청 → 최초 1회 위치 획득(실패 시 서울) → `watchPositionAsync`(정확도 Balanced, 10m 또는 5초 간격). 권한 거부 시 `userLoc`이 `null`로 남고, 사용처마다 `?? SEOUL`로 폴백한다.

**검색/탐색**
- 키워드 검색: Kakao Local `keyword.json` (반경 20km, 현재 위치 기준).
- 카테고리 칩 5종: 음식점 FD6 / 카페 CE7 / 편의점 CS2 / 지하철 SW8 / 약국 PM9 → `category.json`.
- 지역 이동 드롭다운: 도 → 시군구 → 읍면동 선택 → 주소 검색(`address.json`) → `GO_TO`(선택 깊이별 줌 9/7/5).
- 결과는 바텀시트 목록(`검색 결과 N개`, 거리 표시)으로 표시.

**핀/장소 상세 바텀시트** (`_layout.tsx`의 `MapOverlaySheets`, 핀 종류별 버튼이 다름)

| 대상 | 버튼 |
|---|---|
| 랜드마크 | `코스 추천` / `연대기 보기`(피드 탭을 장소명 검색 상태로 이동) |
| 모임 | `모임 보러가기` → `/gathering/{id}` |
| 저장 핀 | `저장 취소` / `게시물 보기` |
| 게시물 핀 | `자세히 보기` / `게시물 보기` |
| 검색·관광지 장소 | `저장하기/저장됨` 토글 / `게시물 보기` |

"게시물 보기"는 `mapStore.feedSearchQuery`에 장소명을 넣고 피드 탭으로 이동 → 피드 검색창이 그 문자열로 채워진다.

**핀 저장(MAP-03/04)**: 장소 상세에서 1탭 저장. 로컬 스토어에 즉시 반영 후 `users/{uid}/savedPins/{placeId}`에 저장(실패는 콘솔 경고만, 롤백 없음). 마운트 시 Firestore에서 전체 로드.

**길찾기 (MAP-07 일부)** — 목적지 검색(300ms 디바운스) 후 3가지 이동수단:

| 수단 | 구현 |
|---|---|
| 자동차 | CF `kakaoDirections` → 소요시간·거리·**택시 요금** + 경로선(꼭짓점 500개로 다운샘플) |
| 대중교통 | CF `odsayDirections`(플랫폼별 키) → 환승 횟수, 첫/막차역, 요금, 구간별 색(지하철 노선 색 14종 매핑, 도보는 초록 점선) |
| 도보 | **직선거리 ÷ 80m/분** 추정 + 점선 (실제 도보 경로 아님) |

응답 경쟁 방지: `dirRequestId` 세대 토큰으로 오래된 응답 폐기.

**지도 공유**: `ShareModal`이 아닌 지도 전용 모달에서 내 채팅방(DM/모임)을 골라 `map_share` 타입 메시지 전송(§3.7).

### 3.4 동네 연대기 — 방문 기반 랜드마크 + 코스 추천 (`utils/postAggregation.ts`)

**새 컬렉션·서버 트리거 없이** 이미 구독 중인 `posts`를 클라이언트에서 집계한다.

| 방문 횟수(같은 `location_pin.id`에 내가 쓴 게시물 수) | 등급 | 마커 |
|---|---|---|
| 1~2 | `flag` 깃발 | 24px |
| 3~6 | `signpost` 이정표 | 28px |
| 7~14 | `house` 집 | 32px |
| 15~29 | `hotel` 호텔 | 36px |
| 30+ | `building` 빌딩 | 40px |

- 색은 앰버 하나로 고정, **모양과 크기로 등급을 구분**(접근성/일관성 결정).
- 좌표가 숫자가 아닌 게시물은 집계에서 제외. `location_pin`이 없는 게시물도 제외.
- 마커 SVG는 `index.tsx`와 `shared-map/[uid].tsx` 두 WebView HTML 문자열에 **중복 정의**되어 있다(공유 불가로 인정한 결정).

**코스 추천 ("빈칸 채우기")** — 랜드마크 핀 → `코스 추천`
1. 현재 위치(없으면 서울) 기준 TourAPI 주변 후보 조회.
2. 후보가 **내 랜드마크에서 50m 이내**면 `visited`(TourAPI id와 카카오 place id는 체계가 달라 좌표로 판정).
3. `buildCourse`: 미방문 우선 → 같은 그룹 안에서는 최근접 이웃 순, 최대 4곳.
4. 구간마다 `kakaoDirections` 호출(자동차 기준)해 앰버 실선으로 그림. 경로 못 찾은 구간은 건너뜀.
5. 후보 0개 → "추천 코스 없음", 경로 0개 → "경로 없음".

> 🟡 출발점은 **선택한 랜드마크가 아니라 내 현재 위치**다. 랜드마크 id를 인자로 받지만 사실상 `id !==` 비교(서로 다른 id 체계라 항상 참)로만 쓰여 효과가 없다. "이 랜드마크에서 출발"이 의도라면 출발점을 명시할 것.
> 코스 1회 = 최대 4회 길찾기 호출 → 일일 한도 50회(§7)에서 빨리 소진된다.

### 3.5 피드/게시물 (POST)

**작성 (`create-post`)**
- 본문 최대 500자(카운터 표시), 사진 최대 5장(이미지 피커 다중 선택), 해시태그는 본문의 `#[\w가-힣]+`를 자동 추출해 미리보기 칩으로 표시.
- 장소 태그: Kakao 키워드 검색 모달 → 선택한 장소 문서 전체를 `location_pin`에 저장(`id, place_name, category_name, address_name, road_address_name, x(경도), y(위도)`) + `location.name`.
- 저장 순서: 문서 생성(`media_urls: []`) → Storage 업로드(`posts/{postId}/{i}.jpg`) → `media_urls` 갱신. 업로드 중 실패하면 **이미지 없는 게시물이 남는다**(트랜잭션 없음).
- 점수: 하루 3회까지 +10, 장소 태그 시 추가 +5. 첫 게시물 뱃지 `first_post`.
- `type`은 항상 `'feed'`. `author_is_sheriff`는 **항상 `false`로 기록**된다(§9).

**피드 (`feed.tsx`)**
- `posts` 전체를 `timestamp desc`로 실시간 구독, 차단 유저 제외.
- 검색: 본문/장소명/태그 부분 일치(클라이언트 필터). 지도에서 넘어온 검색어 자동 적용.
- 카드: 작성자(보안관이면 금색 테두리 + 인증 이미지), 사진 캐러셀, 좋아요, 댓글 수, 공유, 북마크, 본인 게시물 관리 메뉴(삭제).
- FAB/헤더 버튼으로 작성 화면 이동.

**상세 (`post/[id]`)**: 좋아요 토글, 댓글 실시간 목록/작성, 작성자 팔로우, 북마크(`users/{uid}/savedPosts`), 공유(DM으로 텍스트 전송, `share_count +1`), 위치 미니맵(탭하면 지도 탭으로), 더보기 메뉴 → **신고**(타인) / **삭제**(본인).

| 동작 | 점수 |
|---|---|
| 좋아요 받기(본인 제외) | 작성자 +2 |
| 댓글 받기(본인 제외) | 작성자 +3 + 알림 |
| 게시물 삭제 | 작성자 −10 |

- 좋아요 = `likes: string[]` 배열 union/remove (동시성 안전하나 문서 크기 한계 있음).
- 댓글 서브컬렉션 필드는 문서 스키마의 `content`가 아니라 **`text`** (+ `author_nickname`, `author_is_sheriff`).

### 3.6 모임 (GATHERING)

**생성 (`create-gathering`)**
- 유형: **일반** / **번개**.
- 필수: 카테고리(산책·운동/맛집/문화·예술/스터디/취미/봉사), 제목(최대 40자), 소개, 일시, 장소(Kakao 검색), 정원.
- 정원: 2~20명, 기본 4 (**호스트 포함** — 생성 시 호스트가 `participants`에 들어감).
- 일시 입력:
  - 일반 → **요일 다중 선택 + 시각** → 문자열 `"매주 월·수 오전 8:00"`
  - 번개 → **달력에서 날짜(오늘 이전 비활성) + 시각** → `"9월 21일 오후 3:05"` (5분 단위)
- 번개 마감: `1시간 후/2시간 후/3시간 후/6시간 후/오늘 자정` → `deadline_ms` 저장.
- 소개의 해시태그 자동 추출. 생성 시 호스트 +20점, `gathering_host` 뱃지.
- `meeting_at`은 **표시용 문자열**이다(날짜로 파싱해 쓰는 코드 없음 → 정렬·알림·자동 완료 처리 불가).

**목록 (`community.tsx`)**
- 카테고리 스트립 + 검색(제목/소개/장소/태그) + **내 위치 기준 거리순 정렬**(위치 거부 시 정렬 없음, 상태 표시).
- 번개 모임은 마감 시각이 지나면 **목록에서 숨김**(1분마다 재평가). 카드에 남은 시간 표시.
  - 🟡 UI 문구는 "마감 시 자동 삭제"지만 실제로는 Firestore에서 지우지 않고 클라이언트가 걸러낼 뿐이다.
- 카드의 참여 버튼 상태: `참여 신청` → `신청중`(다시 누르면 취소) → `참여확정 ✓` / `거절됨`(사유 표시) / `모집완료`(정원 참).
- 호스트: `참여 관리 (대기 N)` 모달에서 **승인 / 거절(사유 입력, 선택)**, 카드 메뉴에서 삭제.

**상세 (`gathering/[id]`)**: 실시간 구독, 호스트 프로필 이동, 신청/승인/거절, 미니맵, 채팅방 열기, 호스트 전용 **완료(+10)** / **취소(−20)** / 삭제.

**상태 전이**
```
recruiting ──(승인으로 정원 도달)──▶ full
recruiting/full ──(호스트 완료)──▶ completed   (+10 호스트)
recruiting/full ──(호스트 취소)──▶ cancelled   (−20 호스트)
(any) ──(호스트 삭제)──▶ 문서 삭제 (채팅방 있으면 시스템 메시지 "'…' 모임이 삭제됐어요." 남김)
```
- 승인: `pending_requests`에서 제거 → `participants` 추가 → 정원 검사로 `status` 갱신 → **이미 존재하는** 채팅방이면 `members`에 arrayUnion → 참여자 +15점, `gathering_member` 뱃지, 승인 알림.
- 거절: `rejections[uid] = 사유(기본 "모임 조건에 맞지 않아요")` + 알림.
- 신청 → 호스트에게 알림.

> ⚠️ 초기 기획은 "승인 시 채팅방 자동 생성"이라 하지만, 실제는 **호스트가 `채팅방 만들기`를 눌러야** 생성된다(참여자 2명 이상일 때 버튼 노출, 이후 승인되는 멤버는 자동 추가). 채팅방 id = 모임 id.
> ⚠️ `pending_requests[].requested_at`은 항상 문자열 `'방금 전'`으로 저장된다(실제 시각 아님).
> ⚠️ 모임 수정 화면 없음(생성·삭제만). 참여자 스스로 나가기(참여 취소)는 **신청 대기 취소만** 있고 승인 후 탈퇴는 없다.

### 3.7 채팅 (CHAT)

- 방 종류: `dm`(id = `dm_` + 정렬된 두 uid) / `gathering`(id = 모임 id).
- 목록: `members array-contains myUid` 구독, `last_message_at` 내림차순(클라이언트 정렬). DM은 상대 프로필(닉네임) 조회, 모임방은 "모임 채팅" 고정 표기. 미읽음 점(dot) + 탭바 총합 배지.
- 메시지 전송: 메시지 추가 → 방의 `last_message`, `last_message_at` 갱신, 발신자 제외 멤버의 `unread_counts.{uid}` +1.
- 방 진입 시 `markRoomAsRead`(내 카운트 0).
- 특수 메시지:
  - `sender_id === 'system'` → 가운데 정렬 시스템 문구(모임 삭제 안내 등).
  - `type: 'map_share'` → "📍 ○○님이 My Own 지도를 공유했어요" 카드, 탭하면 `/shared-map/{uid}`.
- 나가기: `members`에서 arrayRemove(확인 다이얼로그 "나가면 메시지를 볼 수 없어요").
- 새 DM(`dm/new`): 닉네임으로 유저 검색 → `getOrCreateDMRoom` → 입장.
- 🟡 **유저 검색 버그**: `searchUsers`가 `nickname >= q` AND `nickname <= q + HIGH_SUFFIX`인데 `HIGH_SUFFIX = ''`라서 결과적으로 **정확히 일치하는 닉네임만** 검색된다(접두 검색 의도였다면 `''` 필요).

### 3.8 프로필/소셜/뱃지

**내 프로필 (`profile.tsx`)**
- 헤더: 닉네임(월간 보안관 뱃지 보유 시 방패 아이콘), 등급 칩 + 점수, 통계 3종(저장 장소/팔로워/팔로잉 → 각각 목록 모달, 모달에서 팔로우/언팔로우), 알림 벨(미읽음 배지 9+), 설정.
- 설정: 주거지 인증(미인증일 때만 노출) / 로그아웃.
- 하위 탭: **게시물**(내 게시물 그리드→상세) / **모임**(내가 호스트·참여자인 모임, `호스트` 표시) / **뱃지**(획득 뱃지 카탈로그).
- 점수 모달: `내 활동`(등급 진행 바 + 활동 내역) / `지역 랭킹`(상위 10명, 🥇🥈🥉, 내가 순위권 밖이면 `···` 뒤에 내 줄 추가).
  - 🟡 "활동 내역"의 점수는 `게시물수×10 + 모임참여수×15 + 저장장소수×15 (+주거지 50)`로 **화면에서 단순 곱셈으로 계산한 값**이며 실제 누적 `sheriff_score`와 다르다(일일 한도·좋아요·취소 패널티 등 미반영).
  - 🟡 "지역 랭킹"이라고 표기하지만 `fetchLeaderboard`는 **전국 `sheriff_score` 상위 10명**이다.
- ❌ 프로필 사진 변경: 카메라 버튼에 핸들러가 없고 아바타는 항상 기본 아이콘. Storage 규칙(`profiles/{uid}/…`)만 준비되어 있다.

**타 유저 프로필 (`user/[uid]`)**: 프로필/게시물, 팔로우·언팔로우, DM 보내기, `지도 보기`(→ shared-map), 더보기 메뉴 → 신고/차단·차단 해제.

**팔로우**: 내 `following`에 arrayUnion + 상대 `followers`에 arrayUnion (두 번의 쓰기, 원자적 아님).

**주거지 인증 (USER-04)**: 위치 권한 → GPS → Kakao `coord2regioncode`(행정동 우선)로 "시도 시군구 읍면동" 생성 → 확인 다이얼로그 → `verifyHome`(트랜잭션, **최초 1회 +50점**, `home_verified` 뱃지, `home_location` GeoPoint 저장).

**뱃지 카탈로그** (`constants/badges.ts`)

| 종류 | id | 조건 |
|---|---|---|
| 점수 | `neighborhood_resident` 동네 주민 | 100점 |
| | `regular_visitor` 단골손님 | 300점 |
| | `local_legend` 동네 터줏대감 | 600점 |

### 3.9 보안관 시스템 (점수·등급·월간 뱃지)

**점수표 (실제 코드)**

| 행동 | 대상 | 점수 | 제한 |
|---|---|---|---|
| 게시물 작성 | 작성자 | +10 | 하루 3회 |
| 게시물에 장소 태그 | 작성자 | +5 | 위 한도 안에서만 |
| 게시물 삭제 | 작성자 | −10 | |
| 좋아요 받기 | 게시물 작성자 | +2 | 본인 제외 |
| 댓글 받기 | 게시물 작성자 | +3 | 본인 제외 |
| 장소 저장 | 저장자 | +5 | 하루 5회 |
| 그 장소를 **전체에서 처음** 저장 | 저장자 | +15 | `place_saves/{placeId}` 최초 생성 시 |
| 남이 이미 저장한 장소를 저장 | **최초 저장자** | +3 | 최초 저장자 ≠ 본인 |
| 주거지 인증 | 본인 | +50 | 최초 1회 |
| 모임 개설 | 호스트 | +20 | |
| 모임 참여 승인 | 참여자 | +15 | |
| 모임 완료 | 호스트 | +10 | |
| 모임 취소 | 호스트 | −20 | |
| 퀘스트 완료 | | +30 | ❌ 미구현 |

- 점수는 0 미만으로 내려가지 않음(`Math.max(0, …)`), 변경 시 `rank_level` 재계산.
- **등급**: 새내기(0~99) → 동네 주민(100) → 단골손님(300) → 동네 터줏대감(600) → 지역 인플루언서(1000) → 보안관 후보(2000).
- 일일 한도 카운터: `users/{uid}/daily_stats/{YYYY-MM-DD}` (UTC 날짜 기준, 트랜잭션).
- **서버 측**: `onScoreUpdate` 트리거가 점수 상승 시 마일스톤 뱃지를 한 번 더 부여(클라이언트와 중복 안전장치).
- **월간 보안관 (`monthlySheriffBadge`)**: 매월 1일 00:00 KST. 전체 유저를 `sheriff_score desc`로 읽어 `home_address`에서 정규식으로 구/군/시를 뽑아 지역별 그룹 → 지역별 상위 10명에게 **직전 달** id(`sheriff_2026_08` 등) 뱃지 `arrayUnion`. 점수 0 이하 제외, 주소 없으면 `'전국'` 버킷.
  - 🟡 전 유저를 한 번에 읽고 단일 `batch`로 쓴다 → 유저 수가 커지면 batch 500건 제한과 읽기 비용 문제. 뱃지는 누적만 되고 회수되지 않는다.
  - 🟡 지역 추출 정규식 `(\S+구|\S+군|\S+시)`는 **문자열에서 가장 먼저 나오는 매치**를 반환한다(코드 추론). 주소가 "서울특별시 종로구 청운동"이면 주석이 기대한 "종로구"가 아니라 "서울특별시"가 잡혀, 서울 전체가 한 지역이 되어 TOP 10이 서울 전체에서 10명뿐일 수 있다. "경기도 성남시 분당구"도 "성남시"가 된다. 행정구역 파서를 별도로 만들고 단위(시/구/동)를 명시할 것.

### 3.10 신고/차단 (SAFETY)
- 신고: 게시물(상세 더보기) / 유저(프로필 더보기). 사유 4종(`스팸/광고, 욕설/혐오, 부적절한 콘텐츠, 기타`) 선택 → `reports` 컬렉션에 `status:'pending'`으로 생성. 클라이언트는 읽기·수정·삭제 불가(규칙), 운영자가 콘솔에서 처리. `target_type`에 `comment`가 있으나 댓글 신고 UI는 없음.
- 차단: `blocked_users` 배열. 로그인 시 로드해 `authStore.blockedUsers`에 보관 → `subscribeFeedPosts(…, excludeAuthorIds)`로 **피드·지도(게시물 핀·랜드마크 집계) 게시물만** 제외.
  - 🟡 코드상 댓글·모임·채팅·타 화면에서는 차단 필터가 없다.

### 3.11 알림 (앱 내)
- 저장 위치: `users/{uid}/notifications`. 타입 4종: `join_request`(호스트에게), `join_approved`, `join_rejected`(신청자에게), `comment`(게시물 작성자에게).
- 생성은 **클라이언트가 상대 유저의 서브컬렉션에 직접 write**(규칙이 create를 모든 인증 유저에 허용).
- 화면: 프로필 벨 → 목록 실시간 구독, 탭 시 읽음 처리 + 이동(`comment`→게시물, 나머지→모임). 벨에 미읽음 개수 배지.
- ❌ FCM 푸시, 좋아요/팔로우/채팅 알림 없음.

### 3.12 지도 공유 / 타인 지도 보기 (`shared-map/[uid]`)
- 진입: 타 유저 프로필의 `지도 보기` 또는 채팅의 `map_share` 메시지.
- 표시: 그 유저의 저장 핀(초록) + **그 유저의 랜드마크**(서버 필터 `author_id==uid` 구독으로 집계). 전체 핀이 화면에 들어오게 `setBounds`.
- 빈 상태 조건은 "저장 핀 0개 **그리고** 랜드마크 0개"일 때만(랜드마크만 있어도 지도 표시하도록 수정된 버그 이력).
- 로드 실패 시 재시도 UI.
- 보안: WebView에 주입하는 JSON은 `<`를 `<`로 이스케이프(`</script>` 조기 종료 방지), InfoWindow 텍스트는 `escapeHtml` — 보안 리뷰에서 발견·수정된 항목이므로 **그대로 승계할 것**.
- ❌ 내 지도와 나란히 비교하는 뷰는 후속 과제.

## 9. 기획 ↔ 코드 불일치 & 알려진 결함

### 9.1 동작하지 않거나 의도와 다르게 동작하는 것

1. **점수 지급 vs 보안 규칙 충돌 (가장 중요, 추론)** — `addScore(타인uid, …)`는 `users/{타인}` 문서를 갱신하는데 규칙은 본인 외 update를 `followers` 필드만 허용한다. 영향 경로: 좋아요/댓글 받기(+2/+3), 모임 승인 참여자 +15(호스트가 호출), 최초 저장자 보너스 +3, 그에 따른 마일스톤 뱃지. 코드가 `.catch(() => {})`로 에러를 삼키므로 **조용히 실패**할 가능성이 높다. 점수 집계는 Cloud Functions(트리거)로 옮기고 클라이언트 쓰기를 막는 것이 원래 CLAUDE.md의 의도("Cloud Functions에서 sheriff_score 누적")와도 맞다.
2. **보안관 금색 강조가 사실상 작동하지 않음** — 게시물/모임 생성 시 `author_is_sheriff`, `host_is_sheriff`가 항상 `false`로 저장된다. 월간 뱃지를 받아도 피드·모임 카드의 금색 테두리/인증 이미지는 뜨지 않는다(프로필 방패 아이콘만 `badge_list` 정규식으로 표시). 비정규화 필드 대신 `badge_list`를 조회하거나 서버에서 채워야 한다.
3. **클라이언트 점수 조작 가능** — 점수 갱신이 클라이언트 트랜잭션이라(본인 문서는 쓰기 가능) 자기 `sheriff_score`를 임의로 쓸 수 있다.
4. **이미지 업로드 실패 시 고아 게시물**, 승인/취소 등 다단계 쓰기에 트랜잭션 없음.
5. **유저 검색은 정확 일치만** 됨(§3.7).
6. **번개 모임은 삭제되지 않고 숨겨질 뿐**인데 UI는 "자동 삭제"라고 안내.
7. **모임 채팅방 "자동 생성"이 아님**(호스트 수동).
8. **코스 추천 출발점 = 현재 위치**(선택 랜드마크 아님).
9. **"지역 랭킹"이 전국 랭킹**, 활동 내역 점수는 화면에서 임의 계산.
10. **차단은 게시물만 필터링**, 댓글/모임/채팅은 그대로 노출.
11. **프로필 사진 변경 없음**(버튼만 존재).
12. 완료/취소된 모임 상태는 모집 화면에서는 걸러지지만, 호스트가 `completed`로 바꿔도 목록(`community.tsx`)에서는 status 필터가 없어 계속 보일 수 있음(코드상 status 필터는 지도의 `recruiting`에만 있음).

### 9.2 기획에는 있으나 코드에 없는 것 (❌)
퀘스트 전체(등록/수락/인증사진/포인트 지급, 지도 Quest 탭, 빨간 핀) · 스토리(24시간) · `geohash` 기반 지역 피드 · 동네(읍면동) **하이라이트 오버레이** · 바텀시트 3탭(게시물/장소/모임) 구조 · "주민 저장 수 3개 이상만 핀 노출" 등 **핀 필터링 기준** · 보안관 저장 장소 금색 테두리·"보안관 N명이 저장한 장소" 문구 · 게시물별 현위치 거리 표시 · 애플/구글 외 소셜 확장 · FCM 푸시 · 로컬 코스 경로의 "지도 탭 3-탭" 구조 · Realtime Database 채팅 · 공용 `is_home_verified` 기반 노출 제한.

### 9.3 코드에는 있으나 기획서에 없던 것
번개 모임 유형과 마감, 대중교통·택시요금 길찾기, 동네 연대기(랜드마크 5단계)+코스 추천, 지도 공유 메시지와 타인 지도 보기, 게시물 북마크, 모임 완료/취소 패널티, 거절 사유, 장소 최초 저장자 보너스, 일일 활동 한도, 약관 동의 3종 + 서버 재검증, 신고/차단.

### 9.4 코드 위생
- 죽은 코드: `chat.ts`의 `HIGH_SUFFIX`, `MOCK_PINS = []`, 스토어의 `savedPlaces` 주석(TODO persist), `users.saved_places`/`points` 필드, `react-native-maps` 의존성.
- 거대 파일: `index.tsx` 2,326줄, `profile.tsx` 1,307줄, `community.tsx` 1,044줄 — 컴포넌트/훅 분리 필요(특히 WebView HTML 문자열과 길찾기 로직).

- 카카오 JS 키가 소스에 하드코딩(도메인 제한형 공개 키), Firebase 설정 파일(`google-services.json`, `GoogleService-Info.plist`) 커밋됨. REST/TourAPI 키는 `EXPO_PUBLIC_*` 환경변수(클라이언트 번들에 노출됨 — 공개 키로 취급 필요).

## 11. 개선 로드맵 (요약)

1. **서버가 진실 원천**: 점수·뱃지·`author_is_sheriff`·알림 생성·모임 승인/정원/상태 전이는 Cloud Functions(트랜잭션)로. 보안 규칙은 "본인 문서만 쓰기"를 지키게 하고 모임 `update`의 광범위 허용은 제거.
2. **데이터 모델 정리**: `meeting_at`은 Timestamp(+반복 규칙 필드), 좌표는 GeoPoint + geohash, 참여자는 서브컬렉션(문서 크기 한계·동시성), 좋아요도 카운터+서브컬렉션 검토, 유저는 공개/비공개 문서 분리.
3. **인증 흐름 승계**: 카카오 = 서버 Custom Token + 서버 약관 재검증, 구글 = 웹 클라이언트 implicit 흐름(정적 리다이렉트 페이지), 애플 = iOS 전용, 약관 3종 필수·기기 캐시, `profile_complete` 가드.
4. **지도**: WebView 카카오맵 + 메시지 프로토콜을 타입으로 정의하고 HTML 템플릿·마커를 한 모듈로 공유. 3모드는 유지하되 Quest 모드가 필요한지 먼저 결정.
5. **승계할 검증된 결정**: 랜드마크 5단계(모양·크기로 구분), "빈칸 채우기" 코스, 일일 활동 한도, WebView 주입 XSS 방어(`jsonForScriptTag`/`escapeHtml`), 응답 세대 토큰, 길찾기 일일 한도 + 프록시.
6. **먼저 결정할 것(범위)**: 퀘스트·스토리·푸시·프로필 사진·동네 하이라이트를 1차에 넣을지, 점수표(§3.9)를 그대로 쓸지, "지역 랭킹"의 지역 기준(거주지 인증값 vs 자기 신고값).
